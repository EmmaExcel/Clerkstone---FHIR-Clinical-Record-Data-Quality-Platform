# Clerkstone - Data Provenance, Licences & Citations

> Provenance, licence and citation for every dataset used by Clerkstone. Companion documents:
> [PRIVACY.md](./PRIVACY.md) · [DATA_MINIMISATION.md](./DATA_MINIMISATION.md) · [DATA_MODEL.md](./DATA_MODEL.md).

## 0. The one rule that governs every dataset

> All patient data in this repository is **synthetic**. No real patient data is present, stored,
> processed or transmitted. Any resemblance to a real person is coincidental.

Every dataset below is either (a) generated locally and committed as a small fixture, or (b) a
synthetic/open dataset referenced but **not committed**. Where a dataset is form-gated or
redistribution-restricted, the repository contains **only a link and instructions**, never the data.

## 1. Synthea™ - Synthetic Patient Population Simulator (primary)

| Field | Detail |
|---|---|
| **Dataset** | Synthea™ Synthetic Patient Population Simulator |
| **Source** | MITRE / Synthetic Health - [github.com/synthetichealth/synthea](https://github.com/synthetichealth/synthea) · [synthea.mitre.org](https://synthea.mitre.org) |
| **Contents** | Synthetic longitudinal patients: encounters, conditions, allergies, medications, observations, labs, procedures, care plans, immunisations, providers, payer coverage. Exports FHIR R4 (also STU3, R5), CSV, C-CDA. |
| **Size** | Controlled at generation time. 500 patients ≈ 40 MB FHIR JSON. |
| **Licence** | **Apache-2.0** (verified via GitHub API, 25 Sep 2026; 3,358★; last push 18 Aug 2026) |
| **Commercial use** | Yes Permitted |
| **Portfolio use** | Yes Permitted |
| **Registration / training / DUA** | No None |
| **Committed to repo?** | Only a **20-patient fixture (<1 MB)**; the rest is generated by `scripts/synthesise.py`. |
| **Citation** | Walonoski J, Klaus S, Granger E, Hall D, Gregorowicz A, Neyarapally G, Watson A, Eastman J. *Synthea: An approach, method, and software mechanism for generating synthetic patients and the synthetic electronic health care record.* **J Am Med Inform Assoc.** 2018;25(3):230-238. |

**Note on UK-isation:** Synthea's default geography is US. Clerkstone post-processes it (UK postcodes,
synthetic NHS numbers in the reserved `99…` test range with valid modulus-11 check digits, an
illustrative SNOMED CT / dm+d re-mapping). The **mapping table is illustrative and non-clinical** -
it is not an official NHS mapping and must not be used clinically.

## 2. NHS England Synthetic Clinical Notes (secondary - realism of "dirty data")

| Field | Detail |
|---|---|
| **Dataset** | NHS England Synthetic Clinical Notes (HF) |
| **Use** | Its `admissions.csv` provides realistic NHS-shaped admission structures (`admission_method`, `bed_location`, `site_name`, `ward`, `admission_title`); `patients.csv` provides `nhs_number`, `gender_identity`, `person_id`. Used to model the Encounter projection realistically. |
| **Licence** | **MIT** |
| **Access** | No registration, no DUA |
| **Committed to repo?** | Yes Uploadable (MIT). Committed only as derived field documentation / small fixtures. |
| **Note** | NHS England documents **incorrectly decoded special characters** as a known issue in this dataset - which is exactly the mojibake defect (`STRUCT-004`) Clerkstone detects. |
